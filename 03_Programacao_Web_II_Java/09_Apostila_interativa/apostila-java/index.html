Tipos que aparecem no projeto

  • Integer, Long, Double (com maiúscula) são [wrappers], a versão "objeto" do tipo simples. A diferença que importa: aceitam null. Por isso as entidades ligadas ao banco usam essas versões, já que uma coluna pode ficar vazia.

2. POO do zero

[POO] (programação orientada a objetos) é organizar o código em torno de "coisas". Uma classe é a planta da casa (ou a forma de bolo); um objeto é a casa construída (ou o bolo). Da mesma planta saem várias casas, cada uma com seus próprios dados.

class Filme:
    def __init__(self, nome, duracao):   # construtor
        self.nome = nome                 # atributos
        self.duracao = duracao

    def resumo(self):                    # método
        return f"{self.nome} ({self.duracao} min)"

f = Filme("Matrix", 136)                 # cria o objeto
print(f.resumo())
public class Filme {
    private String nome;                 // atributos
    private Integer duracao;

    public Filme(String nome, Integer duracao) {   // construtor: mesmo nome da classe
        this.nome = nome;
        this.duracao = duracao;
    }

    public String getNome() { return nome; }               // getter: lê
    public void setNome(String nome) { this.nome = nome; } // setter: altera

    public String resumo() {                                // método: String = devolve texto
        return nome + " (" + duracao + " min)";
    }
}
// em outro lugar:
Filme f = new Filme("Matrix", 136);      // 'new' cria o objeto
System.out.println(f.resumo());
  • Atributo: variável que vive dentro do objeto. Método: função que vive dentro da classe.
  • Construtor: método especial chamado pelo new; equivale ao __init__.
  • public = qualquer um acessa. private = só a própria classe acessa. Em Python isso é só combinação; em Java o compilador barra. Isso é [encapsulamento]: proteger os dados e só liberar acesso por métodos.
  • Getter/setter: métodos que leem e alteram um atributo private (getNome(), setNome(...)). Escrever isso à mão é chato, e é aí que entra o Lombok (capítulo 4).
  • O tipo antes do nome do método é o que ele devolve; void = não devolve nada.
Ideia-chave: classe = molde; objeto = coisa criada com new; atributos guardam dados; métodos fazem ações; private protege.

4. Anotações e Lombok

[Anotação] é o @algo escrito em cima de uma classe, atributo ou método. Parece o decorator do Python (@app.route): um adesivo que adiciona comportamento sem você escrever o código. O Spring lê os adesivos e sabe o que fazer com cada classe.

O [Lombok] é uma biblioteca cujas anotações escrevem código chato por você na hora de compilar:

AnotaçãoO que gera
@Getter / @Setterum getX() / setX() para cada atributo
@AllArgsConstructorconstrutor que recebe todos os atributos
@Builderjeito de montar objeto por etapas, nomeando cada campo
Filme f = Filme.builder()      // começa a montar
        .id(1L)                // 1L = long
        .nome("Matrix")
        .build();              // entrega o objeto pronto (campos não citados ficam null)

Vantagem: você não precisa lembrar a ordem dos argumentos de um construtor com 12 campos.

Ideia-chave: anotação = adesivo que gera ou configura comportamento. Lombok gera código; Spring e JPA configuram o resto.

5. Banco de dados e JPA (Filme.java)

O esquema do professor (explicacao.txt), de cima para baixo:

   ▼  JPA               (especificação/regras: as anotações)
   ▼  Hibernate         (implementação do JPA: o ORM)
   ▼  JDBC              (API padrão de Java para bancos)
   ▼  Driver JDBC       (tradutor do seu SGBD: aqui, SQL Server)

[ORM] (mapeamento objeto-relacional) = tabela vira classe, linha vira objeto, coluna vira atributo. Você mexe em objetos e o Hibernate escreve o SQL. Menos SELECT/INSERT à mão.

AnotaçãoSignifica
@Entityesta classe representa uma tabela
@Table(name="TBL_FILME")nome real da tabela no banco
@Ideste atributo é a PRIMARY KEY
@Column(name="...")nome real da coluna
@GeneratedValue(strategy = IDENTITY)o banco gera o id (auto incremento)
@Enumerated(EnumType.STRING)guarda o enum como texto ("ACAO"), não como número
@TransientNÃO vai para o banco (só existe na memória)

Filme.java, linha por linha

package br.com.etechoracio.ingressos.entity;
import ...;                    // enums do projeto, jakarta.persistence.* (JPA), lombok.*, LocalDateTime

@Builder @Getter @Setter @AllArgsConstructor   // Lombok: builder, getters, setters, construtor
@Entity                                         // é uma tabela
@Table(name = "TBL_FILME")                      // a tabela se chama TBL_FILME
public class Filme {
    @Id                                         // chave primária
    @Column(name = "ID_FILME")
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // banco gera o número
    private Long id;

    @Column(name = "TX_NOME")   private String nome;
    @Column(name = "NR_DURACAO") private Integer duracao;

    @Column(name = "TP_CATEGORIA")
    @Enumerated(EnumType.STRING)                // grava "ACAO", "DRAMA"...
    private CategoriaFilmeEnum categoria;

    // classificacao (enum), ano, capa, diretor, elenco, descricao e avaliacao
    // seguem o mesmo padrão: @Column + atributo privado.

    @Column(name = "CHK_EM_CARTAZ")
    private SimNaoEnum emCartaz;                // 'S' ou 'N'

    @Transient
    private LocalDateTime dataExclusao;         // não existe no banco
}

Os prefixos das colunas são um padrão do banco: TX texto, NR número, TP tipo (enum), CHK marcador sim/não, ID chave. O script banco.txt cria a tabela com esses nomes.

6. API REST (FilmeController)

[API REST] é um programa que responde a pedidos [HTTP] (o protocolo da web) com dados, normalmente em [JSON] (texto no formato {"nome": "Matrix"}). O Spring converte objeto Java em JSON e JSON em objeto sozinho.

PedidoAçãoMétodo no códigoResposta
GET /filmeslistar todoslistar()200 + lista
GET /filmes/2buscar umbuscarPorId()200 ou 404
POST /filmescadastrarcadastrar()201 Created
PUT /filmes/2atualizaratualizar()200 ou 404
DELETE /filmes/2apagardeletar()200 ou 404

Códigos de status: 200 = deu certo; 201 = criado; 404 = não encontrado.

@RestController            // classe que responde pedidos web e devolve JSON
@RequestMapping("/filmes") // prefixo de todos os endereços: /filmes
public class FilmeController {

    @GetMapping            // GET /filmes
    public List<Filme> listar() {
        Filme filme1 = Filme.builder().id(1L).nome("Matrix")
                .classificacao(ClassificacaoIndicativaEnum.A16)
                .emCartaz(SimNaoEnum.S).build();
        // filme2 igual, com "Homem aranha"
        return List.of(filme1, filme2);   // lista fixa (imutável): dados de mentira
    }

    List<Long> idsExistentes = List.of(1L, 2L, 3L);   // "banco" de mentira: só guarda ids

    @GetMapping("/{id}")   // GET /filmes/2  -> {id} vira 2
    public ResponseEntity<Filme> buscarPorId(@PathVariable Long id) {  // @PathVariable: pega o {id} da URL
        if (idsExistentes.contains(id)) {
            Filme filme1 = Filme.builder().id(id).nome("Matrix").build(); // (resumido)
            return ResponseEntity.ok(filme1);          // status 200 + o filme
        }
        return ResponseEntity.notFound().build();      // status 404 sem corpo
    }

    @PostMapping           // POST /filmes
    public ResponseEntity<Filme> cadastrar(@RequestBody Filme filme) { // @RequestBody: JSON do pedido vira Filme
        filme.setId(100L);                             // finge que o banco gerou o id
        return ResponseEntity.status(HttpStatus.CREATED).body(filme);  // 201 + filme
    }

    @PutMapping("/{id}")   // PUT /filmes/2
    public ResponseEntity<Filme> atualizar(@RequestBody Filme filme, @PathVariable Long id) {
        if (idsExistentes.contains(id)) { return ResponseEntity.ok(filme); }
        return ResponseEntity.notFound().build();
    }

    @DeleteMapping("/{id}") // DELETE /filmes/2
    public ResponseEntity<Void> deletar(@PathVariable Long id) {  // Void = resposta sem corpo
        if (idsExistentes.contains(id)) { return ResponseEntity.ok().build(); }
        return ResponseEntity.notFound().build();
    }
}

[ResponseEntity] é um "envelope" que carrega o status HTTP junto com o conteúdo. Repare que nada aqui fala com o banco ainda: o controller usa dados de mentira. O próximo passo natural (que você vai ver na aula) é trocar isso por um [repository] do Spring Data JPA.

Ideia-chave: cada anotação (@GetMapping, @PostMapping...) liga um endereço + verbo HTTP a um método. O método devolve o resultado e o Spring transforma em resposta.

8. Pegadinhas do projeto

emCartaz sem @Enumerated. Sem a anotação, o padrão do JPA é gravar a posição do enum (0, 1), mas a coluna guarda 'S'/'N'. Quando o banco entrar em uso, isso costuma dar erro. O conserto é acrescentar @Enumerated(EnumType.STRING), como nos outros enums.
Falta construtor vazio. Com @Builder + @AllArgsConstructor, o construtor sem argumentos deixa de existir, e o JPA normalmente exige um. O jeito comum é somar @NoArgsConstructor.
Senha no código. O application.properties tem usuário e senha do banco escritos, e o projeto vai para o GitHub. Em projeto real, credenciais ficam em variáveis de ambiente ou em arquivo fora do repositório.
